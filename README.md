# Fixture Tracker

A browser tool for looking at tanker fixture data week by week. Dashboard,
charts, a searchable archive, a side by side week comparison, an editable live
week, and a spreadsheet import.

I built this during a summer internship at a shipbroker. Their week lived in a
spreadsheet that got emailed around, and answering a question like "what did
this charterer pay on this route in March" meant opening twelve files. So this
loads the whole history at once and lets you filter it.

**Every fixture in this repo is fake.** Vessel names, charterer names, rates and
dates are all generated by `tools/generate_sample_data.py`. No real fixture,
vessel or counterparty appears anywhere in here. The tool is published with the
company's permission; their data is not part of it.

## Running it

No build step and no dependencies. Serve the folder:

```
python -m http.server 8080
```

Then open http://localhost:8080

## What's in it

| Module | What it does |
|---|---|
| Dashboard | headline counts, status split, top charterers and routes |
| Live Week | the current week, editable, saved to localStorage |
| History | the full archive, filterable by week, charterer, route and status |
| Search | free text across every field in every week |
| Compare | two weeks side by side |
| Import | paste or upload a week from a spreadsheet export |

Roughly 23,000 sample rows across 74 weeks, held in memory. Filtering and
searching all run client side, which is the reason it stays fast enough to be
useful and also the reason it would not survive another few years of data.

## How the data is shaped

Each fixture is a flat array, which keeps the two data files small enough to
ship as plain JavaScript:

```
0 week   1 window  2 vessel  3 charterer  4 mt     5 cargo   6 laycan
7 load   8 discharge         9 rate       10 status  11 notes  12 desk flag
```

Cargo grades (UMS, CPP, NAP, ULSD), port and region codes (ARA, USG, TA, WAFR)
and status codes (FXD, SUBS, FLD) are standard industry shorthand, so the sample
data uses the real ones. That is what makes the demo behave like the real thing.
Vessel and charterer names are invented.

## Regenerating the sample data

```
python tools/generate_sample_data.py
```

Seeded, so it produces the same files every time. Change the seed for a
different set.

`tools/check_no_real_names.py` is the guard. Point it at a private JSON file of
real names and it fails if any of them appear anywhere in the repo:

```
python tools/check_no_real_names.py path/to/private_names.json
```

That file is gitignored and is not in this repo.

## Things I'd change

The whole archive loads into memory on every page. That was the simple thing to
do at 23,000 rows and it is the first thing that breaks at 200,000. A real
version indexes the data once and queries it, rather than filtering an array on
every keystroke.

The five modules also each carry their own copy of the page chrome. That should
be one shared layout.
